1. The problem

A 31-session, 1410-event audit found events.jsonl was logging the right events but losing the data those events need to be judgable. The four-category eval rubric (plan, grounding, verifier, loop) couldn't be scored because:

  • Zero human labels. UserStepAnnotationEvent schema existed; the overlay never emitted one.
  • Frames never persisted. frames/ dir was pre-created but empty; screens were inlined as base64 inside the JSONL.
  • Verifier output truncated. The 4-way verdict (on_track/blocked/diverged/unsure) and screen_summary were logged via Python logger.info only, not into events.jsonl.
  • No LLM I/O captured. No prompts, no raw responses, no tool-call args — only outcomes.
  • Snippet content lost. WebSearchCompletedEvent had source URLs but not the text the planner actually ingested.

Fix 3 — Enrich InstructionVerifiedEvent

The verifier emits {verdict, screen_summary, evidence}; the event was only carrying {ok: bool, reason}. Now the full 4-way label is on the wire.

Schema change 
class InstructionVerifiedEvent(TutorialSessionEventModel):
    type: Literal["instruction_verified"] = "instruction_verified"
    step_id: str
    ok: bool
    reason: str | None = None
    verdict: Literal["on_track", "blocked", "diverged", "unsure"] | None = None
    screen_summary: str | None = None

Emit site updated in tutorial_session.py:1349.

Fix 2 — Frame persistence + content addressing

Every ScreenSnapshot carried in a known client event (user_screen, user_confirmation, user_message.uploaded_images) is now decoded at write time, hashed (sha256), and written to frames/<hash>.<ext>. The JSONL line carries a stable reference instead of inline base64.

Before 
{"event":{"type":"user_screen","request_id":"r1",
  "screen":{"mime_type":"image/png","data_base64":"iVBORw0KGgo...300KB..."}}}
After 
{"event":{"type":"user_screen","request_id":"r1",
  "screen":{"mime_type":"image/png",
            "frame_hash":"a4d3...",
            "frame_ref":"frames/a4d3....png",
            "byte_size":312044}}}

Why it matters:

  • ~100× smaller JSONLs — finally grep-able.
  • Stable handle. UserStepAnnotationEvent.frame_hash now refers to something that actually exists on disk.
  • Dedup. Identical screens collapse to one file (content-addressed).
  • Fail-safe. A bad base64 decode falls back to the original inline snapshot — frame logging never blocks a live tutorial.

Module also got a threading.Lock around JSONL appends since LLM-recorder writes happen from worker threads (next section).

Fix 4b — Snippet content on WebSearchCompletedEvent

The planner ingests the full snippet text. The event used to carry only {title, url}, so a grounding-faithfulness judge had nothing to check claims against. content is now on the wire. 

class WebSearchSource(TutorialSessionEventModel):
    title: str
    url: str
    content: str = ""  # full snippet body

Both enrichment-layer and single-query emit sites pass s.content through. The provider-native search path (LLMWebSearchCompleted) leaves content="" because that API doesn't expose snippets.

Fix 4a — LLMCallEvent + transparent recording

New module backend/llm_recording.py with RecordingLLM: a transparent wrapper around any MultimodalLLM that captures every round-trip without changing call-site code.

Architecture 
main.py WS handler
   └─ event_log = SessionEventLog(session_id)
   └─ store.attach(session_id, emit, llm_call_sink=event_log.write_llm_call)
                                       │
                                       ▼
TutorialSession.__post_init__:
   self.llm          = RecordingLLM(llm,         agent="planner",       sink=sink)
   self.fast_llm     = RecordingLLM(fast_llm,    agent="draft_planner", sink=sink)
   self.verifier_llm = RecordingLLM(verifier_llm,agent="verifier",      sink=sink)

Each call (sync or streaming) produces one LLMCallRecord at completion. The sink:

  1. Writes the full payload to llm_calls/<call_id>.json (prompt_system, prompt_user, response_text, tool_calls).
  2. Appends a compact LLMCallEvent line to events.jsonl with just metadata + payload_ref.
Compact event (in JSONL) 
{"type":"llm_call","call_id":"abc123","agent":"verifier",
 "model":"gemini-2.0-flash","elapsed_ms":312.7,"image_count":1,
 "prompt_system_chars":1284,"prompt_user_chars":612,"response_text_chars":118,
 "tool_calls":[],"ok":true,"error":null,
 "payload_ref":"llm_calls/abc123.json"}
Full payload (sidecar) 
llm_calls/abc123.json
 → { call_id, agent, model, method, elapsed_ms, image_count,
     prompt_system, prompt_user, response_text, tool_calls[], ok, error, extra }

Streaming methods (stream_text, stream_tutorial_tool_calls, stream_tutorial_events) accumulate text and tool calls as they yield, then fire the recorder on exhaustion or exception.

Safety posture:

  • Sink failures are caught and logged — eval logging never breaks a live tutorial.
  • Exceptions in the inner LLM are recorded (ok=false, error=...) then re-raised.
  • Images are never inlined into records — only image_count is stored. Frame bytes already live in frames/.
  • Thread-safe writes via the new SessionEventLog._write_lock.

Fix 1 — Eval-mode toggle in the status bar

The overlay already had sendStepAnnotation(...) in the controller, ✓/✗ buttons gated by @AppStorage("eval_mode_enabled") in ChatPopupView, and the UserStepAnnotationEvent encoder/decoder. The only missing piece: nothing wrote eval_mode_enabled, so it could never be toggled on.

Added a discoverable menu item in StatusBarController: 

// in rebuildMenu():
let evalItem = CallbackMenuItem(
    title: "Eval Mode: \(isEvalModeEnabled() ? "On" : "Off")",
    actionHandler: { [weak self] in self?.toggleEvalMode() }
)
evalItem.state = isEvalModeEnabled() ? .on : .off
menu.addItem(evalItem)

Now toggling the menu item flips UserDefaults["eval_mode_enabled"], which the SwiftUI view observes, which surfaces the ✓ / ✗ buttons next to the step in the popup. Pressing one fires UserStepAnnotationEvent over the WS, with frame_hash already populated from the controller's last masked capture.

ok
coarse boolean (legacy)
reason
free text — error code or LLM evidence
verdict
NEW — on_track | blocked | diverged | unsure | null
screen_summary
NEW — verifier's one-phrase description of the dominant UI

WebSearchSource (in WebSearchCompletedEvent.sources)

title
source title
url
source URL
content
NEW — full snippet text the planner ingested (empty for native provider search)

ScreenSnapshot (in client events, post-substitution)

mime_type
image/png, image/jpeg, image/webp, image/heic, image/heif
frame_hash
NEW — sha256 of the raw bytes
frame_ref
NEW — relative path: frames/<hash>.<ext>
byte_size
NEW — original byte length, for sanity checks
data_base64
removed from the log (still on the wire in-flight)

LLMCallEvent (NEW)

type
"llm_call"
call_id
uuid4 hex
agent
planner | draft_planner | verifier (extensible)
model
best-effort model name (e.g. gemini-2.0-flash)
elapsed_ms
wall-clock for the round-trip
image_count
images in the request
*_chars
lengths of prompts and response
tool_calls
list of {name, arguments_chars}
ok, error
exception capture
payload_ref
llm_calls/<call_id>.json with full prompt + response

4. On-disk layout

├── frames/                   # content-addressed screenshots
│   ├── a4d3...png
