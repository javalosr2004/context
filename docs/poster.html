Thesis. Software documentation is stuck between static GIFs and fragile RPA scripts. A captured demonstration carries enough signal — pixels, keystrokes, intent — to teach the next person, if the system can localize each step on a new screen and gracefully recover when it can't. Context treats that recovery as a first-class UI surface, not a hidden retry loop.

01Problem & Users

Who this is for

  • Power users onboarding teammates to internal tools (CRMs, dashboards, ticketing) whose UI flows aren't documented.
  • Support & CS teams who write the same "click here, then here" emails dozens of times a week.
  • Solo learners following a how-to who lose their place between tab-switches and steps.

Why existing tools fall short

  • Screencasts can't tell you whether you completed step 3.
  • RPA / browser automation brittle on minor UI changes; assumes a stable selector model that desktop apps don't expose.
  • LLM agents over-commit — they take actions when they should be asking.

02Scope of the MVP

In scope. macOS-only. Capture a click/keystroke trace plus screenshots. Replay as an overlay that highlights the next target, asks for confirmation, and replans on divergence.

Explicitly deferred

  • Automation. The system points; the human acts.
  • Generalization across apps. A recording teaches its own flow first; cross-flow transfer is a later phase.
  • PII redaction. Architected to add later without rewrites; not in MVP.
  • Cross-platform. macOS-first; Accessibility APIs avoided so vision-only stack can port.

04The Capture Loop

The recorder is intentionally dumb — it produces a deterministic trace; meaning is layered on later.

  • Inputs. CGEvent tap (clicks, scrolls, key_down, modifier flags); SCStream frames; user-entered goal sheet.
  • Coalescing. Printable keystrokes → "type bursts"; scroll deltas → sessionized scroll events.
  • Outputs. Append-only events.jsonl, content-addressed frames/, per-event crops/ (target + context).
  • No AX. Vision-only by mandate — recordings stay portable to non-macOS targets.

05Enrichment & Replay

Phase 0–2CaptureGoal sheet, frame stream, sessionized scrolls + crops.
Phase 3–4DescribeBundles upload to recording-enrichment; Holo VLM narrates each action.
Phase 5–6VerifySSE progress stream; optional gui-grounding self-check on each described target.
Phase 7ReplayOverlay loads enriched tutorial; live verifier gates step transitions on user screen.

Each phase shipped as its own commit series (phase 0…phase 7), letting the demo regress at any phase boundary.

08The Verification Gate

The replay loop's hardest job isn't planning — it's knowing when the plan is wrong.

  • Strict synchronous gate. The verifier inspects the user's screen before the planner emits the next step (replaces an earlier parallel design — see remove-spaghetti.md).
  • previous_step_visible_effect. Hard-gated check that the prior action actually changed the UI — closes the "model says on_track but nothing happened" loophole.
  • Soft hints. Negative verdicts surface a toast with a user-controlled "replan" button rather than auto-restarting.
  • Clarifying questions. Turn-0 tutorial_ask_user tool lets the planner stall for input instead of hallucinating context.

09Engineering Posture

  • Conventional commits, ruthless scope. 288 commits, almost all feat()/fix(); no merge noise.
  • Schema-first. Pydantic models on the wire; TS bindings auto-generated from Rust where applicable.
  • Layered Swift app. App / Application / Presentation / Domain — pure state logic isolated from NSPanel plumbing.
  • Vision-only mandate. No AX inspector in recorder or replay; keeps the door open for Windows/Linux.
  • Deterministic logs. JSONL + content-addressed frames → every session is replayable for eval.
  • A/B-able prompts. STEP_TOOLS_ENABLED flag toggles capped-head vs. full-plan emission to test the "full-plan hypothesis."

11Open Questions & Next Slice

Live demo gaps

  • Latency budget on the verifier loop when running fully local.
  • Holo description quality on dense UIs (settings panels, IDEs).
  • Replan UX when the user goes off-script intentionally.

Architectural bets to validate

  • Full-plan hypothesis. Re-emit the entire remaining plan each turn; confidence decays, length doesn't.
  • Vision-only forever. Resist the temptation to slip AX in for "just one widget."
  • Recording is the artifact. The tutorial is a view over it, not a separate document.
